# AI 코칭 프로토콜 (정밀 추천 체계) — 설계 스펙

**날짜**: 2026-08-14
**상태**: 사용자 설계 승인 완료 (C안 — 프로토콜 문서 + 분석 스크립트)
**대상**: FORGE40 (`muscle/`) — 대화 기반 AI 운동 추천의 정밀화

## 1. 목적과 범위

"오늘 운동 추천해줘" 류 요청에 대해 AI(Claude, 대화 세션)가 기존 기록·식단·영양 상태·그날의 특이점을 모두 반영해 정밀하게 추천하도록 하는 **운영 프로토콜**을 만든다.

- **실행 위치**: Claude와의 대화. 웹 앱(`muscle/log/`)에 AI를 내장하지 않는다.
- **정밀화 범위**: ① 그날 컨디션 반영(오토레귤레이션) ② 영양·식단 연동 ③ 중량 추천 자체의 정밀화(추세·패턴 인식) ④ 주간 볼륨 관리 — 전부 포함.
- **역할 분담**: 세기·집계·추세 감지는 **스크립트(결정론)**, 판단(종목 대체·RIR 조정·식사 보정)은 **AI**.
- **바꾸지 않는 것**: `log/index.html`의 `recommend()` 이중 점진법과 앱 UI. 프로토콜은 대화용 레이어다.

## 2. 산출물

| 파일 | 종류 | 역할 |
|---|---|---|
| `muscle/COACHING-PROTOCOL.md` | 신규 | 운영 매뉴얼 — 추천 요청 시 AI가 따르는 전체 절차 |
| `muscle/tools/analyze.py` | 신규 | 분석 스크립트 — 추천 전 결정론적 수치 산출 |
| `muscle/log/condition-history.json` | 신규 | 체크인(컨디션·특이점) 기록 누적 |
| `muscle/ACSM-GUIDELINES.md` | 수정 | 8절 절차를 COACHING-PROTOCOL.md로 위임하는 한 줄 추가 (근거 1~7절은 유지) |
| `muscle/CHANGELOG.md` | 수정 | v15로 이번 결정 기록 |

## 3. analyze.py

### 입력
- `muscle/log/history.json`, `nutrition-history.json`, `weight-history.json`, `condition-history.json`
- 기준일 `--date YYYY-MM-DD` (기본: 오늘)

### 출력 (사람이 읽는 텍스트 요약, 섹션 구분)
1. **주간 볼륨** — 최근 7일 부위별 세트수 집계, ACSM 기준(부위별 주 10세트↑·주 2회↑) 대비 부족/과다 표시
2. **세션 빈도** — 최근 7일 세션 이력, 빠진 세션(공백) 감지
3. **종목별 추세** — 각 종목 최근 3~4회 기록의 무게×반복 흐름. 정체(2회 이상 진전 없음)·세트 내 드롭·램프업·상한 도달 표시 + 이중 점진법 규칙에 따른 베이스라인 추천값
4. **영양 요약** — 최근 3일 일별 kcal/단백질(목표 2,700kcal·130g 대비), 연속 미달 여부
5. **체중 추세** — 최근 기록과 월 환산 페이스 (목표 +0.3kg/월 대비)
6. **컨디션 플래그** — condition-history 최근 기록 중 미해결 통증 등

### 설계 결정
- **근육군 매핑은 중복하지 않는다**: 스크립트가 `muscle/log/index.html`의 `SESSIONS` 상수 블록을 직접 파싱해 종목→근육군(m)·lo/hi·inc·alias를 읽는다. 단일 진실 공급원은 HTML 그대로.
- **Fail loud**: SESSIONS 파싱 실패 시 조용히 건너뛰지 않고 즉시 에러 종료 — HTML 형식 변경이 바로 드러나게 한다.
- 의존성 없는 표준 라이브러리 파이썬 (python3만으로 실행).
- 테스트: 현재 커밋된 실제 JSON을 픽스처로 쓰는 검증 (예: 2026-08-13 하체A 기록이 주간 볼륨에 반영되는지).

## 4. 체크인과 condition-history.json

### 체크인 흐름
1. AI가 먼저 데이터를 읽는다 — analyze.py 실행 + 필요 시 원본 JSON 확인.
2. **한 메시지 체크인**: "수면·통증·피로·가용 시간에 특이사항 있으면 알려주세요. 없으면 '평소대로'라고 하시면 됩니다." 직전 기록에 이상 신호(예: 지난 세션 note의 통증 언급)가 있으면 그 항목만 콕 집어 되묻는다.
3. "평소대로"/무언급 항목은 정상으로 간주하고 바로 추천을 진행한다.

### 스키마 (언급된 필드만 기록)
```json
{
  "date": "2026-08-14",
  "sleepH": 5,
  "fatigue": "high",
  "pain": [ {"site": "어깨", "level": "mild", "note": "숄더프레스 시 불편"} ],
  "timeMin": 40,
  "note": "전날 회식"
}
```
- `fatigue`: `low|normal|high`. `pain[].level`: `mild|moderate|severe`.
- 특이사항 없는 날은 `{"date": "...", "normal": true}` 한 줄만.
- 저장은 추천 대화 중 AI가 Edit으로 append. 커밋은 기존 워크플로대로.

## 5. Readiness 조정 매트릭스 (신호 → 조치)

원칙: **세션 통째 취소는 최후 수단** — 벌크업 집중기이므로 축소·대체로 소화한다.
조정 우선순위: **통증 > 시간 > 피로/수면** (안전 > 현실 제약 > 최적화).

| 신호 | 조치 |
|---|---|
| 수면 부족(≤5h) 또는 피로 high | 핵심 종목 유지 + RIR 3으로 여유(증량 보류), 보조 종목 2세트→1세트 또는 생략 |
| 해당 부위 통증 mild | 그 부위에 직접 부하 걸리는 종목만 대체(부위별 대체 테이블은 COACHING-PROTOCOL.md에 명시), 나머지 정상 진행 |
| 해당 부위 통증 moderate 이상 | 그 부위 완전 회피 + 다른 부위 세션으로 교체 제안. 반복되면 병원 언급 |
| 가용 시간 부족 | 핵심 종목만 남기고 보조 컷 — **종목 수를 줄이지, 세트 무게를 줄이지 않는다** |
| 빠진 세션 감지 | v14 규칙: 가장 빠른 다음 기회에 최우선 보충 |
| 연속 정체(같은 종목 3회 진전 없음) | 원인 순서대로 점검: ① 수면·영양 ② 세트 내 드롭 패턴 ③ 디로드 필요(6~8주 경과). 무작정 증량 지시 금지 |
| 사용자 본인이 보고한 관절 이력 | 일반론보다 항상 우선 (ACSM 8절 5항 유지) |

## 6. 영양 연동 규칙 (훈련 유지 + 식사 보정)

- **전날 미달 1일** → 훈련 그대로. 출력에 "식사 보정" 블록: 운동 전 탄수 + 운동 후 단백질, 부족분을 g/kcal 단위로 구체적으로.
- **2일 연속 미달** → 훈련 유지하되 증량 제안 보류(전 세션 무게 반복), 식사 보정 강화.
- **3일 이상 연속 미달** → 이때만 볼륨 조정 언급(보조 종목 축소) + 미달이 구조적인지 대화로 원인 확인.
- **당일**: 마지막 식사가 운동 3시간 이상 전이면 운동 전 간식 제안.
- 판정 기준은 v12 그대로: 최소 충족(단백질 130g↑·2,700kcal↑·지방 55g↑), 탄수는 참고용, 지방·탄수는 질 위주 코멘트.

## 7. 중량 정밀화 (베이스라인 + 오버라이드)

스크립트의 이중 점진법 베이스라인이 출발점. AI는 아래 규칙으로만 오버라이드하며, **오버라이드 시 사유 명시 필수**.

| 상황 | 오버라이드 |
|---|---|
| 세트 내 드롭 (40→40→35) | 증량 대신 "상단 무게로 전 세트 채우기"부터 (ACSM 7절 규칙) |
| 램프업 (30→40→40) | 마지막 무게 기준 판정 — 첫 세트를 웜업으로 간주, 평균으로 오판 금지 |
| 3~4회 추세 상승 + 컨디션 정상 | 베이스라인 그대로 |
| 정체 + 컨디션 신호 있음 | 매트릭스 우선 — 무게 문제로 해석하지 않음 |
| 정체 + 컨디션 정상 + 6~8주 경과 | 디로드 주 제안 (무게 −10~15%, 1주) |
| 직전 기록이 반복 상한 크게 초과 (lo5~hi8인데 15회 등) | 초기 무게 설정 오류로 보고 1스텝 초과 증량 제안 가능 — 단, RIR 확인 질문 후 |
| 첫 시도 종목 | `start` 값 + 유사 종목 기록으로 보수적 제안, 첫 세트에서 조정 안내 |

**금지 규칙 유지**: 실패까지 밀라고 안내 금지(RIR 1~3), 기구 우열 뉘앙스 금지, 복잡한 주기화 도입 금지.

## 8. 출력 형식 (고정)

```
## 오늘의 추천 — {날짜} {세션명}

**판단 근거**: (스크립트 요약 + 체크인 핵심 2~3줄)

| 종목 | 무게×반복×세트 | 전회 기록 | 조정 사유 |
|---|---|---|---|

**식사 보정** (해당 시에만): …
**주의** (통증 대체·웜업 등 해당 시에만): …
```

- "조정 사유" 칸에는 베이스라인 그대로인지, 무엇 때문에 바꿨는지가 항상 보이게 — 결정 추적 가능.

## 9. 전체 절차 (COACHING-PROTOCOL.md의 뼈대)

1. `python3 muscle/tools/analyze.py` 실행 — **수치 암산 금지**
2. 한 메시지 체크인 (직전 이상 신호 있으면 콕 집어서)
3. 세션 결정 — 요일 기본값 < 최근 7일 공백 보충 (v14)
4. 조정 매트릭스 적용 (통증 > 시간 > 피로 순)
5. 종목별 중량 = 베이스라인 + 오버라이드 (사유 필수)
6. 영양 연동 블록 (해당 시)
7. 고정 출력 형식으로 제시
8. 체크인 내용을 condition-history.json에 append

## 10. 테스트 전략

- **analyze.py**: 커밋된 실제 JSON 픽스처 기반 검증 — 주간 볼륨 집계 정확성, 빠진 세션 감지, 드롭/램프 패턴 분류, 베이스라인이 기존 `recommend()` 로직과 동일한 결론을 내는지 대표 케이스 대조. SESSIONS 파싱 실패 시 비정상 종료 확인.
- **프로토콜 문서**: 코드가 아니므로 자동 테스트 없음. 대신 대표 시나리오(정상일·수면부족일·통증일·영양미달일) 각각에 대해 문서만 보고 추천이 한 가지로 결정되는지 자기 점검(모호성 체크) 후 완료.

## 11. 승격 경로 (범위 밖, 기록만)

- 웹 앱에 AI 내장(2단계)은 이번 범위에서 제외. 대화 기반 프로토콜이 검증된 뒤 별도 과제로 재분류한다.
- 기록이 수백 건으로 늘면 analyze.py에 기간 옵션·캐시 등을 추가 검토.
